# Trophy unlocker: source research and first tools

- Audience: owner and contributors; October 22, 2026.
- Scope: Evilnat 4.93, trophy formats, existing editors, native API behavior and an open-source build route.
- Success condition: select an evidence-backed implementation path and produce tested inspection tools before modifying console trophy data.

## Rundown

**Proven from inspected source:** Evilnat's trophy-related Cobra opcodes do not themselves unlock a selected trophy. XAI loads a separate trophyUnlocker.sprx plugin. Apollo supplies a public example of the full file-editing path: transaction decryption, trophy edits, re-encryption and PFD update.

**Proven locally:** the first read-only inspector and bounded SDK downloader pass seven test methods, including malformed layouts, byte limits, deterministic output, preserved input and refused overwrites. These are synthetic fixtures, not a console validation.

**Next:** compile the read-only PS3 discovery probe with the pinned SDK and inspect its output on the target console. Unlock, backup/restore, signing and UI remain separate unfinished implementation work. There is no working unlocker yet.

## Search coverage and source quality

Six Exa search angles requested 30 candidate-result slots: firmware/plugin source, binary layouts, native API lifecycle, SDK/build tooling, protected-file handling, and trophy identity/platinum rules. Duplicated pages, news mirrors, autogenerated summaries and unrelated emulator issues were filtered. Earlier direct searches and GitHub/GitLab source reads supplied additional leads. Candidate-result counts are not a count of independently validated documents, and this is not an exhaustive search of the internet or private Discord servers.

The strongest evidence is the actual maintained code. Wiki and historical editor documentation are useful secondary guides; emulator code is evidence of that emulator's behavior and cannot establish exact behavior on Evilnat hardware. Search-result dates on long-running forum threads are not treated as firmware release dates.

## Findings and implementation consequences

| Class | Finding | Consequence |
| --- | --- | --- |
| Proven in source | Cobra 4.93 CEX main.c: 0x2253 sets hidden_trophy_mode. 0x2254 assigns g_ticks_value. | Neither is a selected-trophy unlock API. Do not call it expecting a trophy unlock. |
| Proven in source | XAI toggle_trophy_unlocker checks Cobra, plugin presence and available VSH slots, then loads a separate plugin with a mode argument. | XAI source is an integration reference; it does not supply that separate plugin's unlock implementation. |
| Proven in source | Apollo resignTrophy decrypts transaction data, applies edits, encrypts it and processes a PFD update. | Our write backend must handle the whole protected set, not just one state field. |
| Proven in source | RPCS3 models context initialization, communication ID/signature checks, registration, trophy range, duplicate unlock and platinum handling. | Native API calls require a valid lifecycle. This is not proof that a standalone app can unlock arbitrary installed titles on a retail PS3. |
| Proven in source | RPCS3 structures use big-endian fields, a 0x30 header and 0x20 table headers. Type-4 entries are 0x60 including header; type-6 entries are 0x70 including header. | The inspector uses explicit byte order and checked offsets; it does not cast host-native C structs. |
| Proven in source | Apollo updates counters, state, timestamps and transaction records. | Preserve unknown fields and ensure consistency. Neither a percentage change nor a file-write success alone proves a correct unlock. |
| Inference / research lead | RPCS3 documents platinum links; historical editor changes describe DLC and ID mapping problems. | Map trophies by explicit IDs and metadata, not row index, and verify base-game/platinum rules separately. |
| Unknown | Exact Evilnat variant, module identities and runtime behavior for our code. | CEX/PEX/D-PEX support remains a target until console evidence exists. No guessed firmware addresses. |

## Negative findings and limits

- The inspected Evilnat GitLab account exposes XAI and Cobra repositories, but no separate trophyUnlocker project appeared in that public project listing. This does not prove the plugin source is unavailable elsewhere.
- The current ps3dev/PSL1GHT tree did not expose a trophy-named header in the inspected inventory. Historical forks are separate leads, not verified current SDK support.
- Local command lookup did not find make, Docker or a PS3 compiler; WSL returned Access is denied. This is a local environment result, not a statement that Windows cannot build PS3 applications.
- No console files, firmware modules, account data or private trophy backups were read or changed. No new hardware result or screenshot exists for this research.

## Reproduce the initial tools

```text
python -m unittest discover -s tests -v
python tools/inspect_trophy.py decoded-TROPUSR.DAT --output new-report.json
python tools/fetch_sdk.py --output sdk.tar.gz
```

The inspector is not a decryptor or an unlocker. The first native probe reads only file headers and writes a new report in its own application directory. Its successful compilation and eventual console test must be recorded separately from these local host tests.
