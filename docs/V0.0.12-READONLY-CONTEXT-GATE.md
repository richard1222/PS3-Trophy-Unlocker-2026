# v0.0.12 — Read-only native trophy-context validation

Status: implementation/test gate; **not** evidence of a working unlocker.
Owner/tester: Richard1222/Saber. Target console: Evilnat 4.93 D-PEX.
Research input: Muse, `PS3-Trophy-Unlocker-Muse-Research.md` (2026-10-23).

## Target and bounds
- Target installed set: Persona 5 (BLUS31604), **NPWR11866_00**.
- Example trophy for future single-trophy testing: **ID 11, Merciless Executioner**. Do **not** unlock it during this milestone.
- Do not modify `TROPUSR.DAT`, `PARAM.PFD`, or other user trophy data.
- Do not call `sceNpTrophyUnlockTrophy` or `sceNpTrophyNetworkSync`; do not issue memory writes or attempt live-folder recovery.
- Preserve/verify a known-good backup before any later write-capable test. Keep the new probe separate from the existing trophy browser and updater.

## Implementation checklist
1. Read installed `TROPCONF.SFM` strictly as data: validate communication ID, trophy count (expected 49), ID range, and 160-byte embedded signature before using fields.
2. Log candidate signature construction explicitly as `SIG_WORD_MAGIC` versus `SIG_WORD_SFM`. The first four bytes' runtime meaning is **unverified on retail firmware**; do not silently hard-code an assumed solution.
3. Create a **separate process-local** trophy context with the documented read-only flag. Do not attempt to import a game's existing context/handle across processes.
4. Gate each lifecycle call: init -> handle -> context -> register -> GetGameInfo/GetTrophyUnlockState -> teardown. Report the raw signed return value and eight-digit hex representation from every step.
5. Confirm registration from successful state reads, not from process presence or trophy folder timestamps alone.
6. Compare returned count and flags with the independent read-only browser; **report mismatch**, never reconcile or rewrite.
7. On any failure, tear down what was allocated and return to the browser safely. Never automatically retry with write permissions.
8. Add a CI/static check that the probe binary has **no references** to `sceNpTrophyUnlockTrophy`, `sceNpTrophyNetworkSync`, file-write APIs for trophy data, or PS3MAPI memory-write actions.

## Console evidence checklist
- Firmware/profile, user slot, game/set, probe build SHA/version.
- Confirmation game is or is not running; **not** proof of an accessible context.
- Return code for every API stage, including status callback events.
- Context registration verdict, returned trophy count and read-only unlock flags.
- Before/after file listing and hashes where permissible, showing user trophy data remained unchanged.
- Repeat after a normal reboot. Avoid PSN sync during the controlled trial.
- Clearly label outcomes: PASS (valid local read-only context and matching data), FAIL (named gate/code), INCONCLUSIVE (missing evidence).

## Go/no-go for single-trophy work
**NO-GO** until native read-only registration succeeds on the target PS3, count/flags match the browser, teardown is clean, and no user trophy files changed. A passing host/mock test or successful PKG launch is not sufficient.

**GO for separate review only** after the above, with explicit user-selected trophy, transactional backup/rollback plan, robust error checks, unchanged-other-trophies checks, local display and reboot-persistence verification. PSN synchronization remains an independent, unverified task.

## Open technical risks
- RPCS3 models APIs but is not guaranteed to match retail Evilnat behavior.
- Foreign-set `TROPHY.TRP` lookup and the runtime signature's first 4 bytes remain unverified.
- A successful read-only context does not demonstrate that a write-capable context can be registered or that PSN will accept a change.
